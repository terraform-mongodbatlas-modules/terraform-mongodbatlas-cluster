# Upgrade Guide: v0.3.x to v0.4.0

This guide covers behavior changes when upgrading to v0.4.0 of the MongoDB Atlas Cluster module. The module remains in public preview; treat upgrades as you would any pre-v1 module.

- [Breaking change: New config server management mode default](#breaking-change-new-config-server-management-mode-default)

## Breaking change: New config server management mode default

Starting in v0.4.0, `config_server_management_mode` defaults to `ATLAS_MANAGED` instead of `null`. In `ATLAS_MANAGED` mode, Atlas automatically transitions the cluster between an embedded config server and a dedicated config server based on shard count, and Terraform does not report these transitions as configuration drift. To pin the cluster to a dedicated config server and prevent automatic transitions, set `config_server_management_mode` to `FIXED_TO_DEDICATED`.

### Why the change?

When `config_server_management_mode` is `null`, Atlas can still transition the cluster's `config_server_type` server-side. Because Terraform tracks `config_server_type`, the next `terraform plan` reports that server-side transition as drift. An explicit `ATLAS_MANAGED` default matches Atlas-managed behavior and keeps that churn out of `terraform plan`.

### Which clusters are affected?

`SHARDED` and `GEOSHARDED` clusters that omit `config_server_management_mode` are affected. After upgrading, `terraform plan` may show an in-place update that sets `config_server_management_mode` to `ATLAS_MANAGED`.

`REPLICASET` clusters are not affected. The module sends `config_server_management_mode = null` for replica sets, which Terraform treats the same as leaving it unset.

Clusters that already set `config_server_management_mode` to `ATLAS_MANAGED` or `FIXED_TO_DEDICATED` are not affected.

### Required action

Accept the plan if Atlas-managed config servers are acceptable, or use the zero-diff option below before upgrading.

### Zero-diff option

Before upgrading, set `config_server_management_mode = null` to keep the previous unset behavior and avoid a plan change:

```terraform
module "cluster" {
  source  = "terraform-mongodbatlas-modules/cluster/mongodbatlas"
  version = "~> 0.4"

  project_id   = var.project_id
  name         = var.name
  cluster_type = "SHARDED"
  regions      = var.regions

  config_server_management_mode = null
}
```

To pin the cluster to a dedicated config server and prevent automatic transitions, set `config_server_management_mode = FIXED_TO_DEDICATED` instead.

No state migration is required. Accepting the new default is an in-place attribute update only.
