# Upgrade Guide: v0.3.x to v0.4.0

This guide covers behavior changes when upgrading to v0.4.0 of the MongoDB Atlas Cluster module. The module remains in public preview; treat upgrades as you would any pre-v1 module.

- [Tags default `null` (Breaking Change)](#tags-default-null-breaking-change)

## Tags default `null` (Breaking Change)

v0.4.0 defaults `tags` to `null` instead of `{}`. Provider state for clusters with no tags is `null`, so an empty-map default caused a non-empty plan after import.

### Who is affected?

Deployments that omit `tags` and currently store an empty map in state may see a one-time in-place plan that sets `tags` to `null`. Callers who already set a non-empty `tags` map are not affected.

### Required action

No action if you accept the plan (no tags on the cluster) or already set real tags. Prefer omit or `tags = null` for import-friendly configs. Avoid `tags = {}` when the cluster has no tags; the provider still treats that as different from `null` after import.

### Zero-diff option

Before upgrading, set an explicit empty map only if you must keep the previous empty-map form in config (import plans may still show a tags update):

```terraform
module "cluster" {
  source  = "terraform-mongodbatlas-modules/cluster/mongodbatlas"
  version = "~> 0.4"

  project_id = var.project_id
  name       = var.name
  tags       = {}
}
```

No state migration is required.

### Why the change?

Import validation needs a clean plan when the cluster has no tags. Matching the provider's `null` avoids a perpetual empty-map update.
