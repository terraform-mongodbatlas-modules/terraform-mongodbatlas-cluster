# Upgrade Guide: v0.3.x to v0.4.0

This guide covers behavior changes when upgrading to v0.4.0 of the MongoDB Atlas Cluster module. The module remains in public preview; treat upgrades as you would any pre-v1 module.

- [Config server management mode default (Breaking Change)](#config-server-management-mode-default-breaking-change)

## Config server management mode default (Breaking Change)

v0.4.0 defaults `config_server_management_mode` to `ATLAS_MANAGED` instead of `null`. Atlas may then switch the cluster's config server type without Terraform plan churn. Set `FIXED_TO_DEDICATED` on the same resource variable when you need a dedicated config server.

### Why the change?

When the attribute is unset, Atlas can change `config_server_type` in ways that show up as plan noise. An explicit `ATLAS_MANAGED` default matches Atlas-managed behavior and keeps that churn out of `terraform plan`.

### Who is affected?

Users who omit `config_server_management_mode`. After upgrading, `terraform plan` may show an in-place update that sets the attribute to `ATLAS_MANAGED`.

Users who already set `ATLAS_MANAGED` or `FIXED_TO_DEDICATED` are not affected.

### Required action

Accept the plan if Atlas-managed config servers are acceptable, or use the zero-diff option below before upgrading.

### Zero-diff option

Before upgrading, set `config_server_management_mode = null` to keep the previous unset behavior and avoid a plan change:

```terraform
module "cluster" {
  source  = "terraform-mongodbatlas-modules/cluster/mongodbatlas"
  version = "~> 0.4"

  project_id   = var.project_id
  name         = var.name
  cluster_type = "SHARDED"
  regions      = var.regions

  config_server_management_mode = null
}
```

Set `FIXED_TO_DEDICATED` instead when you need a dedicated config server.

No state migration is required. Accepting the new default is an in-place attribute update only.
